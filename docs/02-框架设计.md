# 02 - 框架设计

## 1. 总体架构

前后端分离 Web 应用，AI 解析模块作为**独立低耦合模块**挂接在题库域上：

```
┌─────────────────────────────────────────────────────────────┐
│                        前端 (Umi 3 + React)                  │
│  pages/questionBank ──┬─ 操作列「解析」按钮                   │
│                       └─ components/AiAnalysisModal（新增）   │
│  services/requestServices.js ── generateAnalysis 等（新增）  │
└──────────────────────────┬──────────────────────────────────┘
                           │ HTTP（JSON {code,msg,data}，session 登录态）
┌──────────────────────────▼──────────────────────────────────┐
│                   后端 (Spring Boot 2.2.5)                    │
│  LoginHandlerInterceptor ── 全量业务接口鉴权（沿用）           │
│                                                              │
│  ┌──────────── 上游模块（零改动）────────────┐  ┌── AI 模块（新增）──┐
│  │ QuestionBankController   题库/导入/统计   │  │ AiAnalysisController│
│  │ QuestionGenController    组卷/导出/历史   │  │ AiAnalysisService   │
│  │ GeneticIteration 等      算法与 Word 导出 │  │ OpenAiCompatibleClient│
│  └──────────────────────────────────────────┘  └─────────┬──────────┘
│                                                          │ RestTemplate（15s 超时）
│  MyBatis ── MySQL                                        ▼
│  QuestionBank (+analysis 等 3 字段)              第三方大模型 API（OpenAI 兼容）
└─────────────────────────────────────────────────────────────┘
```

## 2. 模块边界（关键设计决策）

| 模块 | 归属 | 改动方式 |
|---|---|---|
| 登录鉴权、题库 CRUD、Excel 导入、遗传/贪心组卷、Word 导出、历史管理、Echarts 统计 | 上游保留 | **代码零改动** |
| QuestionBank 实体 | 上游扩展 | 仅追加 3 个解析字段 + getter/setter |
| QuestionBankMapper | 上游扩展 | 仅追加 `updateAnalysisById`，既有方法不动 |
| application.yml | 上游修改 | 数据库密码改环境变量占位（安全）；追加 `ai.*` 配置段 |
| ai 包（6 个类） | 全新 | 自包含，仅依赖 QuestionBankMapper 与 AiConfig |
| 前端题库页 | 上游扩展 | 操作列追加「解析」按钮 + 挂载弹窗，其余不动 |

**设计约束**（来自需求"低耦合、不破坏原有核心流程"）：
- AI 模块不 import 任何组卷算法类，组卷/导出链路不 import AI 模块类；
- AI 失败只影响 AI 接口自身，返回友好提示，不回写脏数据；
- 解析数据与题目同表（QuestionBank.analysis），导出链路取题目时天然携带，无需 join。

## 4. AI 解析生成流程（时序）

```
教师点击「解析」→ 前端 POST /aiAnalysis/generate {questionId}
  → LoginHandlerInterceptor 校验登录态
  → AiAnalysisService.generateAndSave
      → loadQuestion（查题，不存在则抛 AiException）
      → generate
          → ai.enabled ? OpenAiCompatibleClient.generateAnalysis : mockAnalysis
          → validate（非空 / 长度 ≤ max-analysis-length / 去 ``` 围栏）
      → saveAnalysis（updateAnalysisById，status=1，时间戳）
  → 200 {code:200, data:QuestionBank}  前端展示解析并刷新列表
  → 任一步失败 → 500 {code:500, msg:"友好提示"}，不影响其他功能
```

## 5. 数据设计

解析数据存放在 `QuestionBank` 表新增字段（见 docs/04）：

| 字段 | 类型 | 说明 |
|---|---|---|
| analysis | longtext | AI 生成的解析内容 |
| analysis_status | tinyint | 0 无解析 / 1 已生成 |
| analysis_update_time | datetime | 最近更新时间 |

## 6. 可扩展点（预留接口）

1. **多 Provider**：`AiClient` 接口已定义，新增厂商只需实现该接口并在 Service 中按 `ai.provider` 选择；
2. **批量生成**：`POST /aiAnalysis/batchGenerate` 已实现（顺序执行、单题失败不中断），前端入口未做，见 docs/06 M2；
3. **导出附带解析**：`/questionGen2` 预留 `withAnalysis` 入参（读取逻辑待补），GenWord 模板填充为 M3 迭代项；
4. **PDF 导出、试题标签扩展**：需求已声明预留空间，当前不做。
