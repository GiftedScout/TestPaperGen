# 框架设计

## 1. 系统组成

前后端分离 Web 应用。前端为 Umi + React 单页应用；后端为 Spring Boot REST 服务，通过 MyBatis 访问 MySQL；AI 解析模块作为独立模块挂接在题库域上，经 HTTP 调用第三方大模型。

```
┌──────────────────────────────────────────────────────────────┐
│                      前端 (Umi 3 + React)                     │
│  pages/questionBank ──┬─ 操作列「解析」按钮                    │
│                       └─ components/AiAnalysisModal           │
│  services/requestServices.js ── AI 接口请求函数                │
└───────────────────────────┬──────────────────────────────────┘
                            │ HTTP（JSON {code,msg,data}，session 登录态）
┌───────────────────────────▼──────────────────────────────────┐
│                   后端 (Spring Boot 2.2.5)                    │
│  LoginHandlerInterceptor ── 业务接口登录鉴权                    │
│                                                               │
│  ┌──────────── 组卷域 ────────────┐  ┌─── AI 解析模块 ───┐    │
│  │ QuestionBankController         │  │ AiAnalysisController│   │
│  │ QuestionGenController          │  │ AiAnalysisService   │   │
│  │ GeneticIteration / RandomSelect│  │ OpenAiCompatibleClient│  │
│  │ Topic / GenWord / WordExport   │  └──────────┬─────────┘    │
│  └────────────────────────────────┘             │ RestTemplate │
│                                                  │ 15s 超时     │
│  MyBatis ── MySQL                                ▼              │
│  QuestionBank (含 analysis 等解析字段)        第三方大模型 API   │
└──────────────────────────────────────────────────────────────┘
```

## 3. 模块划分与职责

| 模块 | 包 / 目录 | 职责 |
|---|---|---|
| 登录鉴权 | `config/`、`component/` | 拦截器校验登录态，放行登录/注册/静态资源 |
| 题库管理 | `controller/QuestionBankController`、`services/ExcelReader` | 题目 CRUD、Excel 批量导入、统计查询 |
| 组卷 | `controller/QuestionGenController`、`services/GeneticIteration`、`services/RandomSelectTopic` | 手动组卷、贪心随机组卷、遗传算法组卷、A/B 卷 |
| 试卷导出 | `services/GenWord`、`services/WordExport`、`resources/res/*.ftl`、`resources/templates/*.docx` | FreeMarker/POI 模板填充生成 Word |
| 历史管理 | `controller/*HistoryController`、`entity/*History` | 出卷历史与题目快照的持久化 |
| AI 解析 | `ai/`（6 个类） | 大模型调用、解析生成编排、返回校验、落库 |
| 前端页面 | `src/pages/*` | 登录、题库、编辑、组卷、历史、管理员页面 |
| 前端组件 | `src/components/`、`src/services/` | 解析弹窗、请求封装 |

## 4. 模块边界与修改约束

AI 解析模块与组卷域之间遵循以下约束，变更时不得破坏：

| 约束 | 说明 |
|---|---|
| 依赖单向 | `ai/` 包可依赖 QuestionBankMapper 与 AiConfig；组卷域不得引用 `ai/` 包任何类 |
| 算法不可变 | `GeneticIteration`、`RandomSelectTopic` 的算法逻辑不做修改，参数调优除外 |
| 导出链路兼容 | `GenWord` / `WordExport` 的既有行为保持不变；附带解析能力通过新增参数扩展，不得改变默认输出 |
| 字段扩展方式 | QuestionBank 实体仅允许追加字段；Mapper 仅允许追加方法，既有 SQL 不修改 |
| 失败隔离 | AI 接口的任何失败只影响该接口自身，返回友好提示，不回写脏数据，不中断主流程 |

数据库结构变更见 [docs/04-数据库变更.md](04-数据库变更.md)。

## 5. AI 解析生成流程

```
用户点击「解析」
  → POST /aiAnalysis/generate {questionId}
  → 拦截器校验登录态（未登录 403）
  → AiAnalysisService.generateAndSave
      → 查询题目（不存在 → AiException）
      → 生成解析
          → ai.enabled=true  → OpenAiCompatibleClient 调大模型
          → ai.enabled=false → 返回 Mock 占位解析
      → 校验（非空 / 长度 ≤ max-analysis-length / 去 Markdown 围栏）
      → updateAnalysisById 落库（analysis_status=1）
  → 200 {code:200, data:QuestionBank}
  → 任一步失败 → 500 {code:500, msg:"友好提示"}
```

## 6. 数据模型

解析数据与题目同表存储，导出链路读取题目时自然携带，无需关联查询。

| 表 | 字段 | 类型 | 说明 |
|---|---|---|---|
| QuestionBank | analysis | longtext | AI 生成的解析内容 |
| QuestionBank | analysis_status | tinyint | 0 无解析 / 1 已生成 |
| QuestionBank | analysis_update_time | datetime | 解析最近更新时间 |

其余表结构（User、QuestionLabels、QuestionMaterial、QuestionGenHistory、TestPaperGenHistory）见 `database/base/test_paper_generation_base.sql`。

## 7. 扩展点

| 扩展 | 方式 |
|---|---|
| 接入其他大模型 | 协议兼容（OpenAI chat/completions）的服务只需改 `ai.base-url` / `ai.api-key` / `ai.model`；协议差异大的厂商新增 `AiClient` 实现类 |
| 批量生成 | `POST /aiAnalysis/batchGenerate` 已提供，前端多选入口可按需接入 |
| 导出附带解析 | `/questionGen2` 预留 `withAnalysis` 入参，GenWord 模板填充见路线图 M3 |
| PDF 导出、试题标签 | 数据与接口层预留空间，按需迭代 |
