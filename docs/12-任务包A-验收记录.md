## 1. 交付范围与关键决策

### 1.1 数据模型（`database/migrations/002_task_a_exam.sql`）

| 表 / 字段 | 用途 |
|---|---|
| `exam_publish` | 一次发布：试卷 UID、名称快照、发布人、范围（`all` / `students`）、截止时间、总分、题量 |
| `exam_submission` | 某学生对某次发布的提交状态；`uk_exam_submission(publish_id, student_username)` 唯一 |
| `exam_answer` | 逐题原始作答、判分结果（correct/wrong/pending/ungraded）、判分方式、得分；`uk_exam_answer(submission_id, question_history_id)` 唯一 |
| `question_answer_audit` | 答案治理审计：原值、AI 建议值、确认值、置信度、来源、状态、失败原因、确认人/时间 |
| `QuestionBank` 新增 6 列 | `answer_confirm_status`、`answer_suggest`、`answer_confidence`、`answer_suggest_source`、`answer_confirmed_by`、`answer_confirmed_time` |
| `QuestionBank.answer` / `QuestionGenHistory.answer` | 由 varchar(255) 放宽为 varchar(1000)，避免多空填空答案被截断 |

- 全部新表名为小写，适配 `lower_case_table_names=1`。
- 脚本通过 `information_schema` 判断列是否存在，可重复执行；文件末尾附完整回滚 SQL。
- 未新建试卷快照表，题干/题型/分值/章节/知识点读取既有 `QuestionGenHistory`。

### 1.2 身份与权限

- 不修改既有登录逻辑，只把 `teacher001`、`teacher002` 的 `user_role` 标记为 `teacher`；`admin` 天然具备教师权限；`user` 视为学生。
- 教师接口统一校验 `teacher` / `admin`；学生接口校验登录 + 提交归属。
- 跨人访问返回 `code=403`，截止后提交、重复提交返回 `code=500` 且不写库。

### 1.3 判分口径（`exam/grading/AnswerJudge.java`）

- 仅题型含「选择 / 判断 / 填空」的客观题自动判分；其余一律 `pending`（待评），不给分。
- 多选不给部分分；填空必须全部空正确才得满分。
- 容错：全角/半角、大小写、多选字母顺序、数字等价（`3.0` 与 `3`）、判断题同义写法（`对/√/T/true/1`、`错/×/F/false/0`）。
- 标准答案只读 `QuestionBank.answer` 且必须 `answer_confirm_status=1`；未确认题判为 `ungraded`、0 分，结果页明确注明「答案尚未经教师确认，本题不计分」。
- 判分引擎为纯 Java 类，无 Web 依赖，可直接单测。

### 1.4 提交策略

- 发布时为每个目标学生预建一行 `assigned`。
- 重复提交直接拒绝，不做覆盖；`markSubmitted` 使用 `where status='assigned'` 条件更新，防止并发重复落库。
- 截止校验在任何写库动作之前执行；截止后提交不产生 `exam_answer` 记录。

### 1.5 答案治理

- AI 只写 `QuestionBank.answer_suggest` 与 `question_answer_audit`，绝不直接覆盖 `answer`。
- 唯一生效入口：教师逐题确认（支持采纳建议 / 编辑后确认）；无批量确认。
- 低置信度阈值 0.9，低于阈值在列表中以红色标签强提示；抽检阈值 90%，按题型分层统计「确认值与建议值一致」的占比。
- 格式校验：选择题必须是选项字母组合、判断题必须是二值、填空题按 `|` 拆分非空；格式不符写入 `failed` 审计并记录原因，不写脏数据。
- 未配置真实 AI Key 时使用 mock 建议（`source=mock`，置信度 0.30），仅供离线演示，不可作为验收数据。

### 1.6 报告

- 实时聚合，不落快照表。
- 维度：`chapter_1`（章节）与 `label_1`（知识点）。
- 分母只包含已判定的客观题（`correct` / `wrong`）；`rate = earned / possible × 100`，按得分率升序，薄弱项排在前面。
- 待评（主观题）与未判分（答案未确认）单独计数，不污染得分率。

### 1.7 实时通知

- 原生 WebSocket `/ws/exam`，握手阶段用 HttpSession 鉴权，按用户名维护会话集合。
- 事件：`paper.published`、`submission.received`、`result.ready`；离线丢消息（本期接受）。
- 前端 `ExamSocket` 登录后挂载，断线最多重连 5 次，并派发 `window` 事件供页面刷新列表。

### 1.8 前端路由

| 路由 | 角色 | 页面 |
|---|---|---|
| `/exam` | 学生 | 我的考试 |
| `/exam/answer/:publishId` | 学生 | 在线作答 |
| `/exam/result/:publishId` | 学生 | 作答结果 |
| `/examReport` | 学生 | 学习报告 |
| `/examManage` | 教师/管理员 | 发布、提交列表、班级报告 |
| `/answerAudit` | 教师/管理员 | 答案治理与抽检 |

## 4. 安全底线核对

| 要求 | 实现 |
|---|---|
| 答题响应不得包含答案与解析 | 专用 DTO，无 `answer` / `analysis` 字段；自动化断言覆盖 |
| 提交前不可获取成绩与解析 | `result` 接口要求 `status=submitted`，否则 500 |
| 只能访问发给自己的试卷 | 基于 `exam_submission` 归属校验，跨人 403 |
| 截止后提交拒绝且不落库 | 截止校验前置；自动化验证零写入 |
| 发布/班级报告仅教师与管理员 | `requireTeacher` + 发布者/管理员校验；自动化覆盖 |
