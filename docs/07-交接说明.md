# 开发指南

面向新加入的开发者：从零跑通项目，并快速定位代码与排查问题。

## 1. 环境要求

| 组件 | 版本 | 说明 |
|---|---|---|
| JDK | 8+ | 高版本 JDK 需确认 Maven 编译器级别兼容 |
| Maven | 3.6+ | 依赖下载慢可配阿里云镜像 |
| Node.js | 14+（建议 16） | 前端 Umi 3 时代 |
| MySQL | 5.7+ / 8.0 | 字符集 utf8mb4 |

## 2. 数据库初始化

```bash
mysql -u root -p < database/base/test_paper_generation_base.sql
mysql -u root -p < database/migrations/001_ai_analysis.sql
```

base 脚本自带约 360 道样例题与 7 个账号，可直接体验组卷；当前开发库实际有 589 题（其余为后续导入）。增量脚本可重复执行（幂等）。

> **注意**：样例题的 `answer` 大量为占位 `AAAA`（589 题中 587 题），只影响"答案是否正确"的判题类功能，不影响组卷与解析生成。答案治理方案见 [docs/10](10-任务包A-学生端与判题报告.md) A0。

## 3. 后端启动

依赖：JDK 8、Maven 3.6+、MySQL 已就绪。命令与操作系统无关，`JAVA_HOME` 指向你本机的 JDK 8 即可。

```bash
cd TestPapaerGen-Backend
mvn -DskipTests package
java -jar target/test-paper-generation-3.0.0.jar --server.port=8081
```

- 端口：`application.yml` 默认 **80**；本地联调建议显式给 `--server.port=8081`（也可用环境变量 `SERVER_PORT`），因为前端 `requestConfig.js` 目前按 `:8000 → :8081` 生成 API 地址；
- 数据库：`DB_USERNAME`（默认 root）/ `DB_PASSWORD`（默认 root），可用环境变量覆盖；
- AI 密钥：`AI_API_KEY`，不配则 `ai.enabled=false` 走 Mock 模式；也可登录 admin 后在 `/aiConfig` 页面填写（当前仅本次进程有效，重启失效）；
- 直接在 IDEA 里运行 `TestPaperGenerationApplication` 也可以，请自行配置同样的环境变量。

运行测试：

```bash
cd TestPapaerGen-Backend
mvn -B test
```

依赖下载慢时在 `~/.m2/settings.xml` 里配镜像（例如阿里云），不要依赖某台机器上的离线仓库目录。

## 4. 前端启动

```bash
cd TestPapaerGen-Frontend
npm install
npm start        # 开发服务器 8000 端口
npm run build    # 构建产物在 dist/
```

- `.umirc.ts` 中 `publicPath: "/static/"`；本地开发请求基地址见 `src/config/requestConfig.js`（把后端端口从 8000 映射到 8081）；
- `history.type: 'hash'`，路由刷新不会 404；
- 若 `npm start` 报"npm 不是内部或外部命令"，是 Node 未加入 PATH：把 Node 的安装目录加进 PATH，或直接用 `node node_modules/umi/bin/umi.js dev` 启动。Umi 3 在 Node 17+ 下需要 `NODE_OPTIONS=--openssl-legacy-provider`。

## 5. 目录速查

| 想找什么 | 去哪 |
|---|---|
| AI 模块全部代码 | `TestPapaerGen-Backend/src/main/java/com/teemo/testpapergeneration/ai/` |
| 题库/组卷接口 | `controller/QuestionBankController.java`、`controller/QuestionGenController.java` |
| 组卷算法 | `services/GeneticIteration.java`（遗传）、`services/RandomSelectTopic.java`（贪心） |
| Word 导出 | `services/GenWord.java`、`services/WordExport.java`、`resources/res/*.ftl`、`resources/templates/*.docx` |
| 登录鉴权 | `config/LoginInterceptorConfig.java`、`component/LoginHandlerInterceptor.java` |
| 题库页 AI 入口 | `TestPapaerGen-Frontend/src/pages/questionBank/index.js` 操作列「解析」按钮、顶部「批量生成解析」 |
| AI 配置页 | `src/pages/aiConfig/index.js` + `src/components/AiConfigPanel.js`；顶部导航入口在 `src/layouts/index.js` |
| 请求函数 | `src/services/requestServices.js`（按业务分段，AI 在文件末尾） |

> 开发用的一键启动脚本属于个人环境，**不入库**（见 `.gitignore`）。交接时只交接"前置条件 + 命令"，见第 3、4 节。

## 6. 故障排查

| 现象 | 原因与处理 |
|---|---|
| 接口全部 403 | 未登录。拦截器只放行登录/注册/静态资源，`/aiAnalysis/**` 需要登录态，属预期 |
| 数据库连接失败 | 确认库名 `test_paper_generation` 已导入、`DB_PASSWORD` 已设置；时区看 url 中 `serverTimezone=Asia/Shanghai` |
| AI 生成提示"接口未配置 apiKey" | `ai.enabled=true` 但未配密钥：在 `/aiConfig` 填写、或配 `AI_API_KEY`、或把 enabled 改回 false 用 Mock |
| 配置能保存但解析报"网络失败" | 历史问题：`/aiAnalysis/**` 曾用 `produces=text/plain`，浏览器带 `Accept: application/json` 触发 **406**。现已统一返回 `application/json`，若复现先确认后端 jar 是最新构建 |
| 解析请求成功但弹窗内容为空 | 历史问题：父组件未回写 `currentAnalysisQuestion`，弹窗仍持旧记录。已修，见 `questionBank/index.js#handleAnalysisGenerated` |
| 提示"大模型返回内容为空" | 中转网关偶发空返回。客户端已重试 3 次；仍失败则换模型（推荐 `deepseek-chat`）或换网关 |
| AI 生成慢/超时 | `ai.timeout-ms=15000` 是约束值；国内访问 OpenAI 官方接口不稳定时，换 `ai.base-url` 为国内可达网关 |
| 前端起不来，日志里是乱码行 | 该乱码是 `'npm' 不是内部或外部命令`，即 Node 未在 PATH。用 `node node_modules/umi/bin/umi.js dev` 或把 Node 加入 PATH；看 `logs/frontend.err.log` |
| 前端改了没生效 / build 报 EPERM | Umi 的 babel-loader 缓存被占用：删 `node_modules/.cache` 与 `src/.umi`、`src/.umi-production` 后重启 |
| 端口 80 被占用 | Windows 常见于 IIS/其他服务：改 `server.port`，同步改前端 `requestConfig.js` 端口映射 |
| 端口未监听 | 检查进程是否因父终端退出被回收；用独立终端或 `nohup`/服务方式常驻，不要依赖某个 shell 会话 |
| session 丢失需重新登录 | 后端重启即失效，属正常现象 |

## 7. Git 协作规范

- `main` 保持可编译、可启动；功能开发走 `feature/*` 分支，通过 PR 合并；
- Commit message 格式：`<模块>: <做了什么>`，如 `ai: 新增批量生成接口`；
- 禁止提交：数据库密码、AI API Key、`application-local.yml` 等本地配置（根 `.gitignore` 已屏蔽 `.workbuddy/`、`target/`、`node_modules/` 等）；
- 数据库变更必须新增 `database/migrations/` 编号脚本（幂等 + 回滚说明），不要直接改 base 脚本。
