# 接口文档

## 1. 通用约定

- 响应体统一：`{ "code": 200, "msg": "请求成功", "data": <业务数据> }`；`code=500` 时 `msg` 为友好提示；
- 鉴权：除登录/注册/静态资源外，所有业务接口（含全部 `/aiAnalysis/**`）经过 `LoginHandlerInterceptor`，未登录返回 403；
- 前端请求统一经 `TestPapaerGen-Frontend/src/services/requestServices.js`，用 `checkCode(res)` 判断 `code===200`。

## 2. AI 解析接口

### 2.1 生成并保存单题解析

```
POST /aiAnalysis/generate
Content-Type: application/json

{ "questionId": 1184 }
```

成功（code=200）：

```json
{
  "code": 200,
  "msg": "请求成功",
  "data": {
    "id": 1184,
    "topic": "若机器字长为16位……",
    "topic_type": "填空题",
    "answer": "0~65535",
    "analysis": "本题考查无符号数的表示范围……",
    "analysis_status": 1,
    "analysis_update_time": "2026-10-12 23:10:00"
  }
}
```

失败（code=500）：`{"code":500,"msg":"大模型接口调用失败（网络异常或超时）：…","data":"request parameter error, log time:…"}`

### 2.2 批量生成解析

```
POST /aiAnalysis/batchGenerate
{ "questionIds": [1184, 1186, 1187] }
```

响应 `data` 为逐题结果数组，单题失败不影响其他题：

```json
{
  "code": 200,
  "data": [
    { "questionId": 1184, "success": true,  "analysis": "……" },
    { "questionId": 1186, "success": false, "error": "题目不存在，id=1186" }
  ]
}
```

### 2.3 查询单题解析

```
GET /aiAnalysis/{id}
```

响应 `data` 为完整 QuestionBank（含 analysis 字段）。

### 2.4 手动修改解析

```
PUT /aiAnalysis/{id}
Content-Type: application/json

{ "analysis": "手动编辑后的解析内容" }
```

响应 `data`：`{ "updateStatus": 1 }`。失败：内容为空返回 `解析内容不能为空`；超长返回 `解析内容超长（上限 2000 字符）`。

### 2.5 查询模块状态（脱敏）

```
GET /aiAnalysis/status
```

响应：

```json
{ "code": 200, "data": { "enabled": false, "provider": "openai-compatible", "baseUrl": "https://api.openai.com/v1", "model": "gpt-3.5-turbo", "timeoutMs": 15000, "apiKeyConfigured": false, "apiKeyMasked": "" } }
```

不含 apiKey 明文，只返回脱敏串（如 `sk-****1234`）与是否已配置标志。前端可据此提示「AI 未启用，当前为演示模式」。

### 2.6 管理员运行时配置 AI 参数

```
POST /aiAnalysis/config
{ "enabled": true, "apiKey": "sk-...", "baseUrl": "https://api.deepseek.com/v1", "model": "deepseek-chat" }
```

- 权限：仅 `user_role=admin`，其他角色返回 `code=403`。
- 留空字段保持原值；启用时无有效密钥返回 `code=500` 与友好提示。
- 响应 `data` 为脱敏状态，结构与 2.5 一致，不回显明文密钥。
- 密钥仅存后端运行时内存，不持久化；重启后回落到配置文件/环境变量。

### 2.7 前端服务层对应函数

| 函数 | 接口 |
|---|---|
| `generateAnalysis({questionId})` | POST /aiAnalysis/generate |
| `batchGenerateAnalysis({questionIds})` | POST /aiAnalysis/batchGenerate |
| `getAnalysis({id})` | GET /aiAnalysis/{id} |
| `updateAnalysis({id, analysis})` | PUT /aiAnalysis/{id} |
| `getAiStatus()` | GET /aiAnalysis/status |
| `saveAiConfig(payload)` | POST /aiAnalysis/config |
| `testAiConnection(payload)` | POST /aiAnalysis/test |
| `listAiModels(payload)` | POST /aiAnalysis/models |

### 2.8 连通性测试与模型列表

```
POST /aiAnalysis/test     { "baseUrl": "...", "model": "...", "apiKey": "..." }
POST /aiAnalysis/models   { "baseUrl": "...", "apiKey": "..." }
```

- 字段均可省略，省略时使用当前运行时配置。
- `test` 发一次 `max_tokens=1` 的最小 chat 请求，返回
  `{ ok, latencyMs, model, reply | error }`；错误按 HTTP 状态转为中文提示（401 密钥无效、404 地址不含 /v1、429 限流等）。
- `models` 调 `GET {baseUrl}/models`，返回 `[{ id, ownedBy }]`，用于前端下拉选择。
- 两类接口均不修改运行时配置、不写库。

> 注意：`/aiAnalysis/**` 统一返回 `application/json`。早期用 `produces=text/plain` 时，浏览器 POST 携带 `Accept: application/json` 会触发 Spring 返回 **406**，前端表现为"网络失败、配置不了"。

## 4. 导出附带解析（M3）

| 接口 | 新增参数 | 默认 | 行为 |
|---|---|---|---|
| `POST /questionGen2` | JSON body 中 `withAnalysis: boolean` | false | 新试卷 DOCX 每题下方附带已保存解析 |
| `GET /reExportTestPaper` | query 中 `withAnalysis=true/false` | false | 使用当前题库的题干和解析重新导出 |
| `POST /questionGen` | JSON body 中 `withAnalysis: boolean` | false | 兼容旧 GenWord/FreeMarker 导出链路 |

其余必填参数不变。`/questionGen2` 实际调用 POI WordExport，而非 GenWord。参数省略或 false 时保持原输出；true 时无解析题目仍保留题干，仅省略解析段；解析支持多行及 XML 特殊字符。导出只消费已入库内容，不触发 AI 生成。

历史重导出并非出卷时的内容快照：题库解析后续修改会体现在重新导出的试卷中；已删除题目沿用原逻辑跳过。`/exportAnswer` 不受此参数影响，仍只导出答案。

`/questionGen2` 和 `/reExportTestPaper` 成功返回二进制 DOCX（`application/octet-stream`）；失败时可能为 JSON/text 响应，前端先检查响应状态和类型，避免错误内容被下载为 Word 文件。

## 5. 批量生成解析入口（M2，已接入）

题库页已接入 `/aiAnalysis/batchGenerate` 的前端入口（PR #1）：表格新增「解析状态」列（`analysis_status` 为 1 显示「已解析」，否则「无解析」）并支持按状态筛选；勾选多行后点击「批量生成解析」，结果弹窗逐题展示成功/失败与原因，请求结束后刷新题库列表同步状态列。

前端调用 `batchGenerateAnalysis({ questionIds })`，后端返回 `{code, data: [{questionId, success, analysis | error}]}`。批量执行在服务端为顺序处理，耗时约为题数乘以单题耗时；单题失败不影响其余题目。
