# AI 解析模块设计

AI 解析模块负责调用大模型为题库题目生成解析，是 TestPaperGen 的核心新增能力（对应需求 R-06）。

## 1. 模块结构

包路径：`com.teemo.testpapergeneration.ai`

| 类 | 职责 |
|---|---|
| `AiConfig` | 配置绑定（`ai.*`），含提示词模板、超时、长度上限 |
| `AiException` | 模块统一异常，Controller 捕获后转友好提示 |
| `AiClient` | 大模型客户端接口，后续接入其他厂商只需新增实现 |
| `OpenAiCompatibleClient` | 当前实现：OpenAI 兼容 chat/completions 协议 |
| `AiAnalysisService` | 编排：查题 → 生成 → 校验 → 落库，含 Mock 分支 |
| `AiAnalysisController` | 对外 HTTP 接口 |

## 2. 配置项

`application.yml` → `ai.*`：

| 配置 | 默认值 | 说明 |
|---|---|---|
| `ai.enabled` | `false` | 模块总开关；`false` 时走 Mock 占位解析 |
| `ai.provider` | `openai-compatible` | 提供商标识 |
| `ai.base-url` | `https://api.openai.com/v1` | 接口地址，可替换为任意 OpenAI 兼容网关 |
| `ai.api-key` | `${AI_API_KEY:}` | API Key，环境变量注入，禁止明文提交 |
| `ai.model` | `gpt-3.5-turbo` | 模型名 |
| `ai.timeout-ms` | `15000` | 连接/读取超时 |
| `ai.max-tokens` | `800` | 单次生成最大 token |
| `ai.temperature` | `0.3` | 采样温度，低温保证解析稳定 |
| `ai.max-analysis-length` | `2000` | 解析长度上限（字符），超出视为异常返回 |
| `ai.prompt-template` | 见 yml | 提示词模板，占位符 `{topicType}` `{topic}` `{answer}` |

生产启用：

```bash
export DB_PASSWORD='your_mysql_password'
export AI_API_KEY='sk-xxxx'
java -jar target/test-paper-generation-3.0.0.jar
```

## 3. 提示词设计

模板见 `AiConfig.promptTemplate`（与 yml 一致）：

- 角色：经验丰富的高校教师；
- 约束：聚焦解题思路与关键知识点、不复述题目、与给定答案一致、200 字以内、纯文本无 Markdown；
- 输入：题型 + 题干 + 答案。

调整提示词时只改 `ai.prompt-template` 配置，不需要改代码；调优结论记录到 [docs/06](06-开发任务清单.md) 的调优记录中。

## 4. 调用流程

```
AiAnalysisController.generate({questionId})
  → AiAnalysisService.generateAndSave
      → loadQuestion：查询题目，不存在抛 AiException
      → generate：
          ai.enabled=true  → OpenAiCompatibleClient.generateAnalysis
              POST {baseUrl}/chat/completions
              Authorization: Bearer {apiKey}
              body: model / messages(system+user) / temperature / max_tokens
              解析 choices[0].message.content
          ai.enabled=false → mockAnalysis（占位解析）
      → validate：非空校验 / 长度上限 / 去 Markdown 代码围栏
      → saveAnalysis：updateAnalysisById（analysis_status=1，时间戳）
  → 返回最新题目
```

## 5. 容错行为

| 异常场景 | 处理 |
|---|---|
| 连接失败 / 超时（>15s） | 提示「大模型接口调用失败（网络异常或超时）」 |
| HTTP 4xx / 5xx | 提示携带状态码与响应体的错误信息 |
| 响应缺 choices 字段 | 提示「大模型返回格式异常：缺少 choices 字段」 |
| content 为空 | 提示「大模型返回内容为空」 |
| 返回带 ``` 围栏 | 自动剥除首尾代码围栏 |
| 返回超长（>2000 字符） | 提示超长，不落库 |
| 题目 id 不存在 | 提示「题目不存在，id=…」 |
| 未配置 apiKey 且 enabled=true | 提示「AI 接口未配置 apiKey」 |

所有异常经 Controller 统一转为 `{code:500, msg:"<友好提示>"}`（HTTP 层仍为 200），前端按 code 判断后提示用户。组卷、导出等链路不受影响。

## 6. Mock 模式

`ai.enabled=false` 时 `generate()` 走 `mockAnalysis()`：返回带 `[Mock]` 前缀的占位解析并正常落库。用途：

1. 无 API Key 环境下验证「生成 → 校验 → 入库 → 前端展示」全链路；
2. 前端联调不消耗 token；
3. 演示答辩时避免密钥暴露。

切换到真实大模型：配置 `AI_API_KEY` 环境变量 + `ai.enabled=true`。

## 7. 接入其他大模型

协议兼容（任何支持 `POST {baseUrl}/chat/completions` 的服务，如 DeepSeek、Moonshot、通义千问兼容网关、OneAPI）：只改 `ai.base-url`、`ai.api-key`、`ai.model` 三个配置。

协议差异较大的厂商：新增 `AiClient` 实现类（参考 `OpenAiCompatibleClient`），在 `AiAnalysisService.generate()` 中按 `ai.provider` 分发。

## 8. 安全要求

1. `api-key` 只存在于后端进程环境/配置，严禁写入前端代码、接口响应、git 提交记录；
2. `/aiAnalysis/status` 仅返回 `enabled/provider/model/timeoutMs`，不含密钥；
3. 本地开发不要提交 `application-local.yml` 等含密钥的文件（根 `.gitignore` 已屏蔽）。
