# 03 - AI 解析模块设计

> 本模块是 TestPaperGen 二次开发的**创新点**，对应需求规格第 6 条（P0）。

## 1. 模块结构

包路径：`com.teemo.testpapergeneration.ai`

| 类 | 职责 |
|---|---|
| `AiConfig` | 配置绑定（`ai.*`），含提示词模板、超时、长度上限等 |
| `AiException` | 模块统一异常，Controller 捕获后转友好提示 |
| `AiClient` | 大模型客户端接口（SPI），后续接其他厂商只需新增实现 |
| `OpenAiCompatibleClient` | 当前唯一实现：OpenAI 兼容 chat/completions 协议 |
| `AiAnalysisService` | 编排：查题 → 生成 → 校验 → 落库；含 Mock 分支 |
| `AiAnalysisController` | 5 个 HTTP 接口 |

## 2. 配置项（application.yml → `ai.*`）

| 配置 | 默认值 | 说明 |
|---|---|---|
| `ai.enabled` | `false` | 模块总开关；false 时走 Mock 占位解析，便于无密钥演示联调 |
| `ai.provider` | `openai-compatible` | 提供商标识 |
| `ai.base-url` | `https://api.openai.com/v1` | 接口地址，可换成 DeepSeek/通义/文心等 OpenAI 兼容网关 |
| `ai.api-key` | `${AI_API_KEY:}` | API Key，**环境变量注入，禁止明文提交** |
| `ai.model` | `gpt-3.5-turbo` | 模型名 |
| `ai.timeout-ms` | `15000` | 连接/读取超时，需求约束 15s |
| `ai.max-tokens` | `800` | 单次生成最大 token |
| `ai.temperature` | `0.3` | 采样温度，低温保证解析稳定 |
| `ai.max-analysis-length` | `2000` | 解析长度上限（字符），超出视为异常返回 |
| `ai.prompt-template` | 见 yml | 提示词模板，占位符 `{topicType}` `{topic}` `{answer}` |

生产启用示例：

```bash
# Linux / macOS
export DB_PASSWORD='your_mysql_password'
export AI_API_KEY='sk-xxxx'
java -jar target/test-paper-generation-3.0.0.jar
```

```powershell
# Windows PowerShell
$env:DB_PASSWORD='your_mysql_password'; $env:AI_API_KEY='sk-xxxx'
java -jar target/test-paper-generation-3.0.0.jar
```

或在 IDEA 启动配置的环境变量栏添加同名变量。

## 3. 提示词设计

模板见 `AiConfig.promptTemplate`（与 yml 中一致）：

- 角色：经验丰富的高校教师；
- 约束：聚焦解题思路与关键知识点、不复述题目、与给定答案一致、200 字以内、纯文本无 Markdown；
- 输入：题型 + 题干 + 答案。

调整建议：换题库时优先改 `ai.prompt-template`，不要改代码。

## 4. 容错设计（对应需求"返回格式不稳定"难点）

| 异常场景 | 处理 |
|---|---|
| 连接失败 / 超时（>15s） | `RestClientException` → `AiException("大模型接口调用失败（网络异常或超时）…")` |
| HTTP 4xx/5xx | `HttpStatusCodeException` → 携带状态码与响应体的友好提示 |
| 响应缺 choices / message | 抛 `AiException("大模型返回格式异常：缺少 choices 字段")` |
| content 为空 | 抛 `AiException("大模型返回内容为空")` |
| 返回带 ``` 围栏 | 自动剥除首尾代码围栏 |
| 返回超长（>2000 字符） | 抛超长异常，不落库 |
| 题目 id 不存在 | 抛 `AiException("题目不存在，id=…")` |

所有异常经 Controller 统一转为 `{code:500, msg:"<友好提示>"}`，**HTTP 层仍为 200**，前端用 `checkCode(res)` 判断后 `message.error` 提示。组卷、导出等原有链路完全不受影响。

## 5. Mock 模式（框架演示用）

`ai.enabled=false` 时，`AiAnalysisService.generate()` 走 `mockAnalysis()`：返回带 `[Mock]` 前缀的占位解析并正常落库。用途：

1. 无 API Key 环境下验证"生成 → 校验 → 入库 → 前端展示"全链路；
2. 前端联调不需要消耗真实 token；
3. 演示答辩时避免密钥泄露风险。

切换到真实大模型只需：配置 `AI_API_KEY` 环境变量 + `ai.enabled=true`。

## 6. 接入其他大模型（扩展指南）

任何兼容 OpenAI `POST {baseUrl}/chat/completions` 协议的服务（DeepSeek、Moonshot、通义千问兼容网关、OneAPI 等）只需改 3 个配置：`base-url`、`api-key`、`model`，无需改代码。

协议差异较大的厂商：新增 `AiClient` 实现类（参考 `OpenAiCompatibleClient`），在 `AiAnalysisService.generate()` 中按 `ai.provider` 分发即可。

## 7. 安全要求

1. `api-key` 只存在于后端进程环境/配置，**严禁**写进前端代码、接口响应、git 提交记录；
2. `/aiAnalysis/status` 仅返回 `enabled/provider/model/timeoutMs`，不含密钥；
3. 历史整理中已将上游遗留的明文数据库密码移除（改 `${DB_PASSWORD}`），发现其他残留请立即处理并通知全组。
