# 任务包 A：学生端、自动判题与综合报告

> 独立交付包。可单独拉分支开发，不依赖本包以外的未完成工作（硬前置除外，见第 9 节）。
> 需求来源：用户 2026-11-18 提出的第 1 项需求。

---

## 0. 一句话定位

让教师把已组好的试卷发布给学生，学生在浏览器内作答并提交，系统对**客观题**自动判分、给出全卷解析，教师与学生都能看到该学生的知识掌握报告；同一局域网内的通知实时送达。

## 3. 数据模型

新增迁移脚本：`database/migrations/002_student_assessment.sql`（幂等，可重复执行，附回滚注释）。

```sql
-- 发布记录：一次发布对应一张试卷发给一批学生
create table if not exists paper_assignment (
  id            int not null auto_increment,
  test_paper_uid varchar(255) not null,
  test_paper_name varchar(255),
  teacher_username varchar(255) not null,
  publish_time  datetime,
  deadline      datetime null,
  status        tinyint default 1 comment '1=进行中 2=已截止 3=已归档',
  primary key (id),
  key idx_uid (test_paper_uid),
  key idx_teacher (teacher_username)
);

-- 发布对象：一个 assignment 对每个学生一行
create table if not exists paper_assignment_target (
  id            int not null auto_increment,
  assignment_id int not null,
  student_username varchar(255) not null,
  status        tinyint default 0 comment '0=未提交 1=已提交待判 2=已判分',
  submit_time   datetime null,
  total_score   decimal(6,1) null,
  got_score     decimal(6,1) null,
  primary key (id),
  unique key uk_assign_student (assignment_id, student_username),
  key idx_student (student_username)
);

-- 逐题作答与判题结果
create table if not exists student_answer (
  id            int not null auto_increment,
  assignment_id int not null,
  student_username varchar(255) not null,
  question_gen_history_id int not null comment '指向 questiongenhistory.id，锁定试卷题目快照',
  question_bank_id int null comment '仅用于取解析，可为空',
  answer_text   text comment '学生原始作答',
  is_correct    tinyint null comment '1=对 0=错 null=待评',
  score_got     decimal(6,1) null,
  judge_type    varchar(20) comment 'auto / manual / pending',
  judge_time    datetime null,
  primary key (id),
  unique key uk_answer (assignment_id, student_username, question_gen_history_id)
);
```

### 3.1 questionbank 增补字段（答案治理专用）

```sql
alter table questionbank
  add column answer_suggested   varchar(512) null comment 'AI 反推的答案候选',
  add column answer_status      tinyint default 0 comment '0=未处理 1=待审 2=已确认 3=已驳回',
  add column answer_confidence  decimal(4,2) null comment '模型自评置信度 0-1',
  add column answer_reviewer    varchar(255) null comment '确认人',
  add column answer_review_time datetime null comment '确认时间';
```

注意：
- 表名必须写小写 `questionbank`（Windows `lower_case_table_names=1`）。
- 逐列判断是否已存在再 `add column`，保证脚本可重复执行（历史上 `001_ai_analysis.sql` 在这里踩过坑）。
- **绝不直接覆盖 `answer`**：AI 结果只写 `answer_suggested`，由人工确认后才 `update` 到 `answer`，保证可追溯、可回滚。

约束：
- 所有表名小写（Windows `lower_case_table_names=1`，见 docs/09 第 6 节第 2 条）。
- 不新增"试卷快照表"，直接复用 `questiongenhistory`。
- 报告不落表，实时聚合（数据量小，避免双写不一致）。

## 4. 接口契约

统一返回 `{code, msg, data}`，`application/json`（不要用 `text/plain`，历史上导致过 406，见 docs/09 第 6 节）。

### 答案治理（A0）

| 方法 | 路径 | 说明 |
|---|---|---|
| POST | `/answer/suggest/{questionId}` | 单题反推：调模型 → 写 `answer_suggested` / `answer_confidence` / `answer_status=1`；不覆盖 `answer` |
| POST | `/answer/suggest/batch` | body `{questionIds:[]}` 或 `{topicType:"选择题", limit:50}`；顺序执行，单题失败不影响其他 |
| GET | `/answer/pending` | 待审列表，分页 + 按题型筛选，返回题干、原答案、AI 建议、置信度 |
| POST | `/answer/{questionId}/confirm` | body `{answer}`（可采纳 AI 建议或人工改写）→ 写回 `answer`，`answer_status=2`，记录审核人与时间 |
| POST | `/answer/{questionId}/reject` | `answer_status=3`，保留原值，不参与判题直到重新处理 |

反推提示词要求（写进代码常量，便于追溯）：
- 输入题干 + 题型 + 知识点；输出**只要答案本身**，格式按题型固定：选择题 `A` / `AB`，判断题 `对` / `错`，填空题多空用 `；` 分隔。
- 要求模型同时给出 0–1 的自评置信度；解析失败或格式不符则该题标 `answer_status=0` 并记录原因，不写脏数据。
- 置信度 < 0.7 的题在待审列表中默认置顶并标红，提示必须人工核对。

抽检策略（必须写进验收记录）：
- 按题型分层抽检，每题型至少 20 条，人工核对后记录准确率；准确率 < 90% 的题型，整类回退为人工补齐。

### 教师侧

| 方法 | 路径 | 说明 |
|---|---|---|
| POST | `/assignment/publish` | body: `{testPaperUid, studentUsernames:[], deadline}`；校验 `user_role=teacher` 或 admin |
| GET | `/assignment/teacher/list` | 我发布的试卷 + 每张的提交进度 |
| GET | `/assignment/{id}/submissions` | 该次发布的全部学生：状态、得分、提交时间 |
| GET | `/report/class/{assignmentId}` | 班级维度：平均分、及格率、逐题正确率、知识点薄弱项 |

### 学生侧

| 方法 | 路径 | 说明 |
|---|---|---|
| GET | `/assignment/student/list` | 我的试卷：待完成 / 已完成 |
| GET | `/assignment/{id}/paper` | **必须剔除 `answer` 字段**，只返回题干、题型、分值、序号；若已截止返回 403 提示 |
| POST | `/assignment/{id}/submit` | body: `{answers:[{questionGenHistoryId, answerText}]}`；写 `student_answer` 后立即判客观题、写 `total_score/got_score/status` |
| GET | `/assignment/{id}/result` | 逐题：我的答案、正确答案、对错、得分、解析（`questionbank.analysis`）；主观题标注"待评" |

安全底线（必须做，属于验收项）：
- `/paper` 响应体不得出现 `answer`、`analysis`；用专门 DTO，禁止直接返回实体。
- 提交前不可访问 `/result`。
- 学生只能访问 `paper_assignment_target` 中存在自己的 assignment，其余返回 403。

### 消息

- `GET /ws/notify`（WebSocket，`@ServerEndpoint` 或 Spring `WebSocketHandler`）：按用户名推送。
- 事件：`paper.published`（教师发布）、`paper.submitted`（学生提交，推给教师）、`paper.graded`（出分，推给学生）。

## 5. 判题规则（精确到可写单测）

只对三种客观题判分：`选择题`、`判断题`、`填空题`。其余题型（程序分析题 / 程序设计题 / 程序阅读题）一律 `judge_type=pending`、`score_got=null`。

判题只读 `questionbank.answer`（人工确认后的值），**不读 `answer_suggested`**。未确认（`answer_status != 2`）的题在发布时计入"答案未完善"数量，学生端该题作答题照常记录，但不计分（`judge_type=pending`，备注"答案待完善"）。

### 归一化预处理（所有题型共用）

1. 去首尾空白；全角转半角（`，。；：（）` → `,.;:()`）。
2. 连续空白压缩为单个空格。
3. 大小写：选择/判断忽略大小写；填空默认忽略大小写（可配置开关）。

### 选择题

- 标准答案 `answer` 形如 `A`、`AB`、`A,B`、`A B`。
- 拆分：去掉所有非字母字符后逐字母比较，**排序后集合相等**才算对。
- 多选少选一律判错（不做部分分）。
- 正确得该题 `score` 满分，否则 0。

### 判断题

- 标准答案归一：`对/正确/√/T/true/1` → `T`；`错/错误/×/F/false/0` → `F`。
- 学生答案同规则归一后比较。

### 填空题

- 标准答案按分隔符拆空：`；`、`;`、`|`、`,`、`、`、连续空格。
- 学生按空提交（前端渲染 N 个输入框，N = 标准答案拆出的空数）。
- **逐空比对，全部空正确才得满分**（不做按空比例给分，本期简化）。
- 容错：数字等价值判断（`1` 与 `1.0`、`０` 全角数字）视为相同。

### 单测要求

`JudgeServiceTest` 至少覆盖：多选乱序、少选、全角、大小写、多空全对、多空部分对（判错）、判断题 T/F/√/× 四种写法、主观题不判分。≥ 15 个用例。

## 6. 前端页面

路由（`.umirc.ts`）：

| 路由 | 页面 | 角色 |
|---|---|---|
| `/student` | 我的试卷 | student |
| `/student/exam/:id` | 答题页 | student |
| `/student/result/:id` | 成绩与解析 | student |
| `/report` | 综合报告 | student / teacher 共用，按角色渲染 |
| `/questionGenHistory` | 增加"发布"按钮 | teacher |
| `/answerReview` | 答案审核（A0） | admin / teacher |

交互要点：
- 学生登录后跳 `/student`，不再进 `/home`（教师端功能对其隐藏，导航按 `user_role` 区分）。
- 答题页左侧题号导航（已答/未答）、倒计时（有 deadline 时）、提交二次确认。
- 提交后直接跳结果页，客观题立刻显示对错；主观题显示"待教师评阅"。
- 结果页按知识点分组展示正确率（用 `label_1` / `chapter_1`）。
- 教师"发布"弹窗：选择学生（全选/按用户名搜索）、设置截止时间；若该卷含未确认答案的题，弹窗顶部提示"N 题答案待完善，将不计入自动评分"。
- 答案审核页：左侧题型筛选 + 待审数量徽标，右侧逐题卡片（题干、原答案、AI 建议、置信度、采纳/改写/驳回），支持键盘 `J/K` 切换、`Enter` 确认，保证批量抽检效率。

## 7. 局域网消息方案

- 后端新增 `spring-boot-starter-websocket` 依赖。
- `NotifyEndpoint` 用 `ConcurrentHashMap<String, Session>` 按 username 保存在线会话；登录时不在线则丢弃消息（本期不做离线队列）。
- 前端在登录成功后建立连接，断开后 5s 重连，最多 5 次。
- 消息体：`{type, title, payload, timestamp}`，前端用 antd `notification` 展示。
- 前置：学生机必须能通过教师机 IP 访问前端与后端，见包 B 的 B4；本包只负责建立连接与推送。
