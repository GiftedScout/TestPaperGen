# 任务包 A：学生端、自动判题与综合报告（任务书）

> **文件性质**：这是任务书，不是实现规格。文中标注为「约束」「契约」「判定口径」「安全底线」的内容不可协商；其余实现细节（页面形态、接口命名、表结构、组件划分等）由承接开发者自主决定，并在交付说明中记录其决策与理由。
>
> 需求来源：用户 2026-11-18 提出的第 1 项需求。对齐结论见第 12 节。

---

## 1. 要解决的问题

现在教师出完卷只能导出 docx，学生在纸上做、教师手工批，系统在"导出"这一步就断了。

本期要把**发布 → 作答 → 判分 → 反馈 → 复盘**这条闭环收进系统内：学生提交后立刻知道哪些题错了、错在哪个知识点，教师不用逐份批客观题就能看到班级整体掌握情况。

**成功的第一判据是这条闭环能被完整走一遍**，而不是功能条目数量。任何一项做得再精致，闭环断了都不算交付。

---

## 2. 交付目标

1. 教师能把已组好的试卷发给指定学生（或全班），并设截止时间。
2. 学生在浏览器内作答并提交；客观题即时出分，主观题明确标注"待评"，不让学生误以为提交失败。
3. 学生能看到逐题对错、正确答案与全卷解析。
4. 学生与教师都能看到该生的知识掌握报告（按章节/知识点维度的得分率），教师另有班级维度视图。
5. 同一局域网内，发布、提交、出分这些事件能实时到达对端浏览器。
6. 判分必须基于题库真实答案 —— 因此需要先把占位答案治理为可用数据（见第 7 节 A0）。

---

## 3. 范围边界

**做**：试卷发布与截止控制、学生端列表与答题、客观题自动判分、成绩与解析页、个人与班级报告、局域网实时通知、答案数据治理。

**不做**（明确划出，避免范围蔓延）：

- 不做防作弊（切屏检测、摄像头、强制锁屏）。只做"截止后不可提交"。
- 不做主观题自动给分。程序分析题 / 程序设计题 / 程序阅读题共 114 题，只展示解析并标"待评"。
- 不做公网部署、多学校多租户、家长端。
- 不改遗传 / 贪心组卷算法，不改 docx 导出主流程（零改动原则）。
- 不做离线消息队列：对方不在线则消息丢弃，本期接受。

---

## 4. 不可协商的约束

1. **技术栈不变**：Java 8 + Spring Boot 2.2.5 + MyBatis + MySQL 8；前端 Umi 3 + React 16 + Antd 4。不得引入需要 Java 11+ 或 React 17+ 的依赖。
2. **上游保留模块零改动**：组卷算法、导出链路、既有登录/题库/管理员功能不得修改行为。
3. **数据库变更走 `database/migrations/` 编号脚本**：幂等（可重复执行）、附回滚说明。本包占用 `002_` 段，不要改 `base` 与已合入脚本。
4. **表名一律小写**：目标环境存在 `lower_case_table_names=1`，写大写在部分平台会找不到表。
5. **接口统一 `{code, msg, data}` + `application/json`**。不要再用 `produces="text/plain"` 这类声明 —— 历史上浏览器带 `Accept: application/json` 时触发过 406，整条 AI 链路因此"看起来是网络故障"。
6. **密钥与密码不得出现在源码、前端产物、日志、git 提交中**。
7. **既有测试不得回归**：现有 23 项后端测试必须全绿。

## 5. 只与包 B 约定的几件事

包 A 与包 B 并行开发，只有以下接口需要冻结，其余互不干涉：

| 事项 | 约定 |
|---|---|
| 页面外壳 | A 复用 B 提供的布局与页面容器，**不自建第二套**。B 需在开工后尽早给出该外壳的使用契约（props 语义 + 一段用法示例），A 据此写页面；命名不限。 |
| 请求层 | A 不得自行拼接主机与端口，统一调用 B 的请求配置层；A 只追加自己的接口函数。 |
| 导航与路由 | A 只追加自己的路由与菜单项，不重构导航结构。 |
| 合并顺序 | **B 先合入 main，A 从最新 main 拉分支**。B 动的是骨架，反序会让 A 的每个页面改两遍。 |

若 B 的改造尚未落地，A 可先用临时占位外壳推进后端与判题逻辑，但**不得**把占位壳合入主干。

## 6. 数据职责（不规定具体 DDL）

数据模型由开发者设计，但必须满足以下语义，缺一不可：

- 能表达「一次发布 = 一张试卷发给一批学生」，并记录发布者与截止时间。
- 能表达「某学生对某次发布的提交状态、提交时间、总分与得分」。
- 能表达「某学生对某道题的原始作答、判分结果、判分方式（自动/人工/待评）、判分时间」。
- 必须能唯一约束"同一学生对同一题只保留一份有效作答"，重复提交要么拒绝、要么覆盖（策略自定，需在文档写明）。
- **复用既有试卷快照**：`questiongenhistory` 已按 `test_paper_uid` 逐行保存题干、答案、分值、题型、章节与标签，即试卷内容已固化。**不要新建试卷快照表**，否则同一份数据两处维护。
- 答案治理需要的新增字段归本包负责，随 `002_` 脚本一并提交，必须能追溯"建议值 / 确认状态 / 置信度 / 确认人与时间"。
- 报告默认实时聚合、不落表。若开发者判断必须落快照（例如数据量或性能理由），需在交付说明中给出测算依据。

## 7. 业务判定口径（影响正确性，必须按此实现）

### A0 答案数据治理

**已知事实**：题库 589 题中 587 题的 `answer` 是占位符 `AAAA`。不治理，判分结果全部错误，功能等于不可用。治理方式经用户确认为「AI 反推 + 人工抽检」：

- AI 只产出**建议**，**绝不直接覆盖** `answer`。必须经过人工确认才生效。
- 必须可追溯：谁确认、何时确认、原值是什么、模型给的建议值是什么、置信度多少。
- 低置信度的题必须在审核界面上显眼到无法被批量无脑通过。
- 必须给出抽检方法与准确率记录（按题型分层）。准确率不达标的题型回退人工补齐；阈值建议 90%，最终值与用户确认。
- 反推结果必须按题型可解析、可校验：选择题是选项字母组合，判断题是二值，填空题多空可拆分。格式不符的不得写入脏数据，应标记为处理失败并记录原因。

### 自动判分

- **范围仅客观题**（选择题 / 判断题 / 填空题）。其余题型一律"待评"，不参与自动评分。
- 判分必须读**人工确认后**的题库答案；未确认的题不计分，且要在学生端注明原因，不能静默给 0 分。
- 多选不给部分分；填空本期"全部空正确才得满分"（不做按空比例给分）。
- 必须容错等价写法：全角/半角、大小写、多选顺序、数字等价形式（`1` 与 `1.0`）、判断题的 `对/√/T/true/1` 一类同义写法。具体归一化规则由开发者实现，但必须被测试覆盖。
- **判题逻辑与 Web 层解耦**，可直接单测；判分规则表要能被非开发者读懂（教师会质疑"为什么这题判错了"）。

## 8. 安全与权限底线（验收直接判定）

- 答题接口的响应**不得包含答案与解析字段**，用专门 DTO，禁止直接返回实体。
- 学生提交前不可获取成绩与解析。
- 学生只能访问发给自己的试卷；跨人访问必须 403，不能靠前端隐藏。
- 截止后提交被拒绝，且不写入任何作答数据。
- 发布、查看班级报告仅教师与管理员可用。

## 9. 验收（用户视角，实现自由）

每条都应能被非开发者按顺序点击复现。

| 编号 | 操作 | 通过标准 |
|---|---|---|
| A-1 | 教师组一张含 9 题的卷并发布给 2 名学生 | 教师端出现该卷，进度显示 0/2 |
| A-2 | 学生 A 登录 | 首页/列表出现该卷，状态"待完成" |
| A-3 | 学生 A 打开答题页并抓取网络响应 | 响应中不含答案与解析相关内容 |
| A-4 | 学生 A 客观题全对、主观题留空后提交 | 客观题得分为满分合计；主观题标"待评"且不计入自动评分 |
| A-5 | 学生 A 查看结果页 | 逐题对错、正确答案、解析均正确；主观题显示"待评"及原因 |
| A-6 | 教师在提交列表中查看该生 | 状态与得分与学生端一致 |
| A-7 | 打开报告页 | 按知识点/章节给出得分率，薄弱项可排序 |
| A-8 | 教师发布时，另一台同局域网机器上的学生端 | 无需刷新即收到通知 |
| A-9 | 学生 B 尝试访问他人试卷的结果 | 返回 403 |
| A-10 | 截止后提交 | 明确提示已截止，且数据库无新增作答 |
| A-11 | 对 10 道占位答案题执行批量反推，再确认其中 5 道 | 仅这 5 道答案被更新且状态为已确认；其余 5 道原值不变 |
| A-12 | 发布含"答案未确认"题目的试卷并作答该题 | 该题不计分，结果页注明原因，试卷总分口径正确 |

**自动化要求**：判题规则必须有单测覆盖全部分支（多选乱序、少选、全角、大小写、多空全对/部分对、判断题多种写法、主观题不判分）；发布与越权、重复提交要有接口层测试。用例清单写进验收记录，不规定条数。

## 12. 需求对齐结果（2026-11-18 用户已确认）

| 决策项 | 结论 | 影响 |
|---|---|---|
| 判题范围 | 仅客观题自动判分 | 主观题只展示解析、标"待评"，不做 AI 判分链路 |
| 答案治理 | AI 反推 + 人工抽检确认 | 建议值与原值分离，人工确认后生效，可追溯 |
| 学生账号 | 沿用注册 + 管理员审核 | 复用既有注册与审核链路，只需补学生端入口 |
| 报告形态 | 实时聚合，不落快照表 | 避免双写不一致 |
| 实时通知 | 真·实时（WebSocket 或等价） | 需引入对应依赖，注意与 Java 8 的兼容 |
| 部署前置 | 依赖包 B 的同源部署与请求层改造 | 学生机才能从局域网访问 |

以上为已定结论。如需变更，请在本节追加变更记录，不要静默改动范围。
