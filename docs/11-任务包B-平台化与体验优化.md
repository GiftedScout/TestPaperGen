## 1. 要解决的问题

系统现在处于"能跑的原型"状态，四个问题都被用户明确点过：

| 编号 | 现象 | 根因 |
|---|---|---|
| B-1 | 界面简陋 | 直接沿用上游 antd 默认样式，没有主题、没有层级，表格表单全平铺 |
| B-2 | AI 参数不透明 | 管理端只看得到 4 个字段，提示词、温度、长度、超时只能改配置文件 |
| B-3 | 重启丢配置 | AI 配置是内存态，进程一重启就回落到配置文件 |
| B-4 | 只能 Windows 启动 | 启动脚本硬依赖 PowerShell 与本机便携 MySQL 路径 |

本包要把它变成"可交付、可维护、换个操作系统也能跑"的系统。**判据不是改了多少页面，而是接手人能不能不读一堆口头交代就把系统跑起来、把 AI 调明白。**

## 2. 交付目标

1. 界面具备现代后台系统的基本观感与一致性：信息层级清楚、同类元素表现一致、视觉令牌集中可换。
2. 管理员能在界面上看到**运行时真正生效的每一个 AI 参数**（含提示词全文）及其来源，能在不重启的前提下修改、验证、复原。
3. 配置重启不丢，密钥不以明文落盘，文件损坏不导致系统起不来。
4. 开发与部署不再绑定 Windows / PowerShell，也不再依赖写死的主机与端口。

---

## 3. 范围边界

**做**：视觉与交互重构、AI 参数完整暴露、配置持久化、跨平台启动与部署路径、请求地址去硬编码、CORS 收紧。

**不做**：

- 不换框架、不引入 TypeScript 重写（保持 Umi 3 + React 16 + Antd 4，避免与包 A 大面积冲突）。
- 不改业务逻辑与组卷算法，本包只动"壳 + 配置 + 启动"。
- 不做暗色主题、不做国际化、不接 CDN、不做 SaaS 化与多租户。
- 不重构权限模型（沿用 admin / teacher / user）。

---

## 4. 不可协商的约束

1. **技术栈不变**，与包 A 保持同一基线，不得单独升级 React / Antd / Spring Boot。
2. **主题与视觉令牌集中定义**，页面里不得散落硬编码颜色与间距 —— 否则以后换主题要改上百处。这不限制你选什么颜色，只要求"能一处改全站"。
3. **既有 AI 接口保持向后兼容**：`/aiAnalysis/config`、`/aiAnalysis/status` 当前已有前端调用，扩展字段可以，破坏现有请求/响应含义不可以。
4. **配置不得明文存密钥**，不得提交进 git 仓库目录，不得下发到前端，不得写进日志。
5. **部署不得把主机、端口、数据库连接写死在源码**；CORS 不允许"通配来源 + 允许携带凭证"并存（现有实现属于安全债，必须收敛）。
6. **既有测试与既有功能不回归**：现有 23 项后端测试必须全绿，登录/题库/组卷/导出/解析全流程可用。

## 6. B1 界面现代化

### 目标

让第一次打开系统的人不觉得这是 2015 年的后台模板；让日常使用者能快速回答三个问题：我在哪、这页能干什么、主要操作在哪。

### 判断标准（可验收，不规定做法）

- **层级**：每个页面有明确的页面级标题与主操作区，正文内容有容器边界，不出现"标题和表格直接贴在白底上"。
- **一致性**：同一语义的元素在不同页面表现一致 —— 主按钮、次按钮、危险操作、状态色、间距节奏。抽查任两个数据页面，同类元素的样式值应当相同。
- **令牌集中**：主题色、圆角、字号、间距集中定义，页面内无散落色值（自查方式：全局搜索颜色常量，应只出现在主题定义处）。
- **三态齐全**：数据类页面都有明确设计的加载态、空态、错误态，不能是 antd 默认空表格。
- **首因页面**：登录页与首页承担"第一印象"，不允许仍是默认模板直出。
- **布局可用**：1280 宽及以上无横向滚动、无元素重叠；窄屏下不塌陷（折叠/抽屉均可）。
- **表单体验**：错误提示指向具体字段，提交中状态明确，破坏性操作有二次确认。

视觉风格、配色方案、布局形态（顶部/侧边/混合）、组件命名与数量由你决定。交付时附一页设计说明：为什么这样分层、为什么选这套配色、哪些地方刻意保持克制。

## 7. B2 AI 参数治理

### 目标

"诚实展示"的含义是：管理员能看到**运行时真正生效的每一个参数**，以及它来自哪里、被谁覆盖，而不是看到一个只有四个输入框的表单。

### 判断标准

- **覆盖完整**：AI 调用链上所有可调项都能在界面看到并修改 —— 至少包括：启用开关、接入地址、模型、密钥、超时、生成长度上限、采样随机性、输出长度校验、提示词全文。今后新增参数不得只能靠改配置文件。
- **来源可见**：每个参数能看出当前值来自哪里（配置文件 / 环境变量 / 磁盘 / 本次运行内修改），以及是否被上层覆盖。
- **可验证**：能对当前配置发起一次真实的最小调用验证，并把结果翻译成人能读懂的结论（密钥无效、地址缺版本段、限流、服务异常要能区分）。现有的连通性检测接口可扩展，不要另起一套。
- **可复原**：单个参数与整页都能恢复默认，且恢复后重启仍是默认值。
- **可追溯**：变更有记录（时间、操作者、改了哪些项、旧值→新值；密钥只记"已更换"，不记值）。保留条数自定。
- **提示词可验证**：编辑器支持占位符，并能用一道真实题目预览"替换后的最终文本"，避免盲改提示词。占位符集合必须与代码里实际使用的一致。
- **安全**：仅管理员可见可改，非管理员 403；明文密钥不回显、不下发前端、不写日志。

页面布局、字段命名、编辑交互、历史展示形式由你决定。若你认为某个参数不该暴露（例如内部调试项），在交付说明中说明理由。

## 8. B3 配置持久化

### 目标

管理员配置一次，重启后仍然生效；密钥不以明文落盘；文件异常不导致系统启动失败。

### 判断标准

- **重启保持**：配置与密钥保存后重启服务，AI 直接可用，无需重新填写。
- **明文不落盘**：落盘文件内容与日志中都不得出现明文密钥；文件权限尽力收紧。
- **来源优先级明确**：多层配置（运行内修改、磁盘、环境变量、配置文件）的优先级必须定义清楚，写进文档，并在启动日志里打印当前生效来源。
- **写入可靠**：原子写入，避免写到一半断电造成配置损坏；损坏时能降级启动、保留现场（坏文件另存），并给出可读提示。
- **失败必报**：磁盘只读、权限不足时必须明确报错并回滚内存值，不允许"看起来保存成功"。
- **不污染仓库**：配置目录不在 git 工作区内，且被忽略规则覆盖。
- **可迁移**：配置目录位置可通过环境变量覆盖（默认放用户主目录即可）。

存储格式、加密算法与密钥管理方式、目录命名、是否加密存储的具体实现由你决定。**不加密不在自由范围**：若要存明文，必须先向用户说明风险并获得确认。

## 9. B4 跨平台运行与部署

### 目标

不绑定 Windows，也不绑定某个人的机器。任何人拿到仓库，按文档就能在自己的环境里跑起来；部署不受操作系统限制。

### 判断标准

- **交付的是"启动方式"，不是"启动脚本"**：仓库需要提供前置依赖、环境变量清单与标准命令，照着能起服务。**不接受**把某台机器的绝对路径（JDK / Maven / MySQL / Node 安装位置、数据目录、便携工具链）写进仓库 —— 这类内容对他人无效，还会让人误以为"必须这么放"。
- **可移植**：起服务与构建的步骤在至少两种操作系统上等价可用（bash 与 PowerShell 两种写法），不依赖某一家的专有语法或预装工具。
- **失败可读**：端口占用、依赖缺失、版本不符要给出具体原因与下一步，不允许静默退出或只抛堆栈。
- **便捷脚本的处置**：允许个人写脚本，但只能留在本地并被忽略；若要随仓库提供，必须零硬编码（全部从 PATH / 环境变量推导，缺依赖时提示而非报错退出），并明确标注为可选便利手段，不是唯一入口。
- **地址不写死**：源码中不得出现写死的主机与端口；接口基地址由运行时配置或同源相对路径决定；端口、数据库连接由环境变量或配置提供。
- **部署入口单一**：前后端对外一个入口、无跨域，或给出你能论证的等价方案。若沿用"前端产物由后端托管"，注意构建产物的资源路径前缀必须与托管方式一致（现为 `/static/`，改托管方式时不同步就会白屏或 404）。
- **局域网可用**：同网段其他机器能完整使用（这条同时解除包 A 的阻塞）。
- **容器化（可选，建议做）**：若提供，`docker compose up` 后无需手工建库即可登录使用；容器内的表名大小写行为要与既有环境一致。

具体的操作系统与版本、是否保留脚本、是否容器化、是否用反向代理，由你决定。验收记录必须写明"实测于哪种环境、哪些路径没覆盖"。

## 11. 已知事实与陷阱（省时间用，不是指令）

- 前端请求基地址目前由 `src/config/requestConfig.js` 做字符串替换（`:8000` → `:8081`），换端口、反代、同源部署全部失效，是本包要处理的根因之一。
- 构建配置 `publicPath` 现为 `/static/`，与"后端静态托管"方案冲突，改托管方式时必须同步验证。
- 历史事故：AI 接口曾声明 `produces="text/plain"`，浏览器带 `Accept: application/json` 触发 406，前端显示为"网络失败"。改接口时不要再引入内容协商冲突。
- 本地开发曾依赖一份**未入库**的 PowerShell 启动脚本，里面写死了本机的 JDK / Maven / MySQL 路径。这类脚本已移出版本控制，文档改为通用命令 —— 这正是 B4 要解决的"环境绑定"问题的一个样本。
- 前端偶发 babel 缓存 `EPERM`，删 `src/.umi*` 后重试即可。
- PowerShell 5.1 在 `HTTPS_PROXY` 与 `https_proxy` 同时存在时 `Start-Process` 会报错，脚本环境变量需做大小写归一。
- Windows 上 `git commit -m "中文"` 会乱码，需写 UTF-8 文件后 `-F` 提交。
- 后端 `server.port` 默认 80，本地脚本用 8081；两处口径不同，改造时统一为一处来源。
- AI 现有参数项与默认值见 `application.yml` 的 `ai.*` 段与 `docs/03`，以代码为准。
