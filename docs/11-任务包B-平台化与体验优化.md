# 任务包 B：界面现代化、AI 配置治理与跨平台运行

> 独立交付包。可单独拉分支开发。本包先于包 A 合并（原因见第 8 节）。
> 需求来源：用户 2026-11-18 提出的第 2、3、4、5 项需求。

---

## 0. 一句话定位

把当前"能跑的原型"改造成"可交付的系统"：界面不再像 2015 年的后台模板，AI 的每一个参数（含提示词全文）都在管理端如实可见可改，配置重启不丢，且不再只能用 Windows PowerShell 启动。

## 3. B1 视觉与交互现代化

### 3.1 设计基线

- 主色 `#2f54eb`（或用户指定），中性灰阶沿用 antd，圆角 8px，卡片阴影 `0 1px 2px rgba(0,0,0,.06)`。
- 在 `.umirc.ts` 配置 antd 主题变量（umi 3 内置 less 变量注入）：

```ts
theme: {
  '@primary-color': '#2f54eb',
  '@border-radius-base': '8px',
  '@card-radius': '8px',
  '@font-size-base': '14px',
}
```

- 字体栈：`-apple-system, "Segoe UI", "PingFang SC", "Microsoft YaHei", sans-serif`。

### 3.2 布局重构

现状是顶部横排 Menu，页面无层级。改为：

```
┌──────────────────────────────────────────────┐
│ 顶栏：Logo / 系统名        当前用户 / 角色 / 退出 │
├──────────┬───────────────────────────────────┤
│ 侧边导航  │ 面包屑                            │
│ (可折叠)  │ 页面标题 + 主操作按钮             │
│          │ 内容卡片区（Card 包裹）            │
└──────────┴───────────────────────────────────┘
```

- 侧边导航按角色渲染菜单（admin / teacher / user 三套，`user_role` 来自 `loginModel`）。
- 页面级统一结构组件 `components/PageContainer`：`{title, subTitle, extra, children}`，所有页面替换为它包裹。
- 移动端 ≤ 768px 时侧边栏收起为抽屉。

### 3.3 组件规范（供包 A 复用）

必须新建并统一使用：

| 组件 | 用途 |
|---|---|
| `PageContainer` | 页面标题 + 面包屑 + 操作区 |
| `DataTableCard` | 表格 + 工具栏 + 分页的统一壳（题库、历史、用户管理都换成它） |
| `StatusTag` | 统一状态色（已解析/无解析、进行中/已截止、待评/已评） |
| `EmptyState` | 空态插画 + 主操作按钮（替换 antd 默认空态） |
| `LoadingSkeleton` | 表格与卡片的骨架屏 |

### 3.4 逐页改造清单

| 页面 | 改造点 |
|---|---|
| `/login` | 左右分栏（左品牌区、右表单卡），不再是一张孤零零的白卡 |
| `/home` | 数据概览卡片（题库题数、试卷数、已解析率），图表用 ECharts |
| `/questionBank` | 顶部操作区合并为工具条；筛选区可折叠；行内操作收进"更多"下拉 |

## 4. B2 管理端完整暴露 AI 参数

### 4.1 原则

"诚实展示"= 管理端能看到**运行时真正生效的每一个参数**，包括它的**来源**与**是否被覆盖**，而不是只显示几个字段的表单。

### 4.2 参数表（全部可见、可改）

| 参数 | 类型 | 默认 | 说明文案（必须展示） |
|---|---|---|---|
| `enabled` | boolean | false | 关闭时解析走 Mock 占位，不产生真实调用 |
| `provider` | string | openai-compatible | 当前仅支持 OpenAI 兼容协议 |
| `baseUrl` | string | https://api.openai.com/v1 | 需含 `/v1`，否则 404 |
| `apiKey` | string | 空 | 脱敏显示 `sk-****后四位`，只写不读 |
| `model` | string | gpt-3.5-turbo | 建议 `deepseek-chat` |
| `timeoutMs` | int | 15000 | 单次请求读超时，过大易造成前端长时间等待 |
| `maxTokens` | int | 1200 | 解析要求 200 字以内，过小会截断 |
| `temperature` | double | 0.3 | 越低越稳定，>0.7 可能出现与答案矛盾的表述 |
| `maxAnalysisLength` | int | 2000 | 超过视为异常返回并拒写库 |
| `promptTemplate` | text | （现有模板） | 支持 `{topicType}` `{topic}` `{answer}` 三个占位符 |

### 4.3 交互要求

1. **来源标注**：每个参数右侧显示徽标 `文件` / `环境变量` / `运行时` / `磁盘`，鼠标悬停说明"当前值来自哪里、被谁覆盖"。
2. **提示词编辑器**：TextArea 全屏编辑 + 占位符高亮 + "用当前题目预览渲染结果"按钮（后端 `POST /aiAnalysis/preview`，传入 `questionId` 返回最终 prompt 文本）。
3. **恢复默认**：每个参数一个重置图标，一键回落到 `application.yml` 值；整页提供"全部恢复默认"。
4. **生效方式**：保存后立即生效（写内存 + 落磁盘，见 B3），并在页面顶部提示"已生效，重启后保持"。
5. **危险操作**：清空 Key、关闭 AI、恢复默认都要二次确认。
6. **保存历史**：记录最近 10 次修改（时间、操作者、改了哪些字段、旧值→新值，Key 只记"已更换"）。

### 4.4 接口

| 方法 | 路径 | 说明 |
|---|---|---|
| GET | `/aiAnalysis/config/full` | 返回全部参数 + 每个参数的 `source` + `defaultValue` |
| POST | `/aiAnalysis/config` | 扩展为接受全部字段（现有接口复用，保持向后兼容） |
| POST | `/aiAnalysis/preview` | body `{questionId}`，返回渲染后的 prompt 与 token 估算 |
| POST | `/aiAnalysis/config/reset` | body `{keys:[]}` 或空表示全部 |
| GET | `/aiAnalysis/config/history` | 最近 10 条变更 |

权限：全部仅 `user_role=admin`，非管理员 403（沿用现有实现）。

## 5. B3 配置磁盘持久化

### 5.1 存储位置（跨平台）

优先级：`APP_CONFIG_DIR` 环境变量 > 用户主目录下的 `.testpapergen/`。

- Linux/macOS：`~/.testpapergen/config.json`
- Windows：`%USERPROFILE%\.testpapergen\config.json`

目录不存在则创建；文件权限尽力收紧（POSIX `chmod 600`，Windows 用 ACL 说明，不做强依赖）。

### 5.2 文件格式

```json
{
  "version": 1,
  "updatedAt": "2026-11-18T19:00:00+08:00",
  "ai": {
    "enabled": true,
    "provider": "openai-compatible",
    "baseUrl": "https://api.deepseek.com/v1",
    "model": "deepseek-chat",
    "timeoutMs": 15000,
    "maxTokens": 1200,
    "temperature": 0.3,
    "maxAnalysisLength": 2000,
    "promptTemplate": "你是一名经验丰富的高校教师...",
    "apiKeyEnc": "base64(AES-GCM)",
    "apiKeyMasked": "sk-****1c8e"
  }
}
```

- `apiKey` **不存明文**：用 AES/GCM/NoPadding 加密，密钥从 `~/.testpapergen/master.key`（32 字节随机）读取，首次自动生成。
- 提供开关 `storeApiKeyPlain`（默认 false，仅本地演示可开），开启时写入 `apiKeyPlain` 并在 UI 明示风险。
- 文件必须加入 `.gitignore`（`**/.testpapergen/`）。

### 5.3 加载优先级（必须写进文档与启动日志）

```
运行时（本次进程内修改）
  > 磁盘 config.json
    > 环境变量 AI_API_KEY / 配置项
      > application.yml
```

启动时打印一行：`[cfg] ai config source=disk enabled=true model=deepseek-chat key=****1c8e`。

### 5.4 实现要点

- 新增 `ConfigStore`（`com.teemo.testpapergeneration.ai.config`）：`load()` / `save()` / `getSource(key)` / `reset(keys)`。
- `AiConfig` 改造为"运行时视图"，启动时由 `ConfigStore` 注入初值。
- 保存失败（磁盘只读、权限不足）必须回滚内存值并返回明确错误，不能"看似保存成功"。
- 写入用"临时文件 + 原子重命名"，避免写一半断电导致配置损坏；损坏时备份为 `config.json.bad` 并回落 application.yml。
- 单测：`ConfigStoreTest` 覆盖加密往返、原子写、损坏恢复、优先级、重置。

### 5.5 验收

| 编号 | 操作 | 通过标准 |
|---|---|---|
| B3-1 | admin 配置 Key 并保存，重启后端 | `/aiAnalysis/status` 仍为 enabled=true、同一模型；解析直接可用，无需重配 |
| B3-2 | 查看 `~/.testpapergen/config.json` | 无明文 Key，只有 `apiKeyEnc` |
| B3-3 | 删除 master.key 后启动 | 启动不崩溃；Key 视为未配置并给出提示，其余参数正常 |
| B3-4 | 手工把 config.json 改坏 | 启动回落 application.yml，坏文件被备份为 `.bad` |
| B3-5 | 恢复默认 | 文件与内存同时回落，重启后仍是默认值 |

## 6. B4 跨平台启动与部署

### 6.1 目标

- 不依赖 PowerShell；Linux/macOS 用 `scripts/dev.sh`，Windows 用 `scripts/dev.ps1`，二者行为一致。
- 提供 `docker compose up` 一键起全套（MySQL + 后端 + 前端）。
- **彻底移除 `:8000` → `:8081` 的硬编码**。

### 6.2 API 地址改造（关键）

现状 `src/config/requestConfig.js`：

```js
export const API = window.location.origin.replace(":8000", ":8081");
```

问题：换端口、反代、同源部署全部失效。

改为：

```js
// 优先运行时注入，其次同源相对路径
export const API = window.__APP_CONFIG__?.apiBase ?? "";
```

- **开发模式**：umi `proxy` 把 `/aiAnalysis`、`/login` 等转发到 `http://127.0.0.1:8081`，前端代码里不再出现端口。
- **生产模式：同源部署（已确认，本期唯一方案）**。`umi build` 产物由 Spring Boot 静态托管，只暴露一个端口。
  - 必须先把 `publicPath` 从 `/static/` 改为 `/`，否则 `index.html` 里引用的 `/static/umi.js` 会 404。
  - dist 内容复制到 `src/main/resources/static/`，`index.html` 放 `static/index.html`；后端加一个 fallback 控制器，未匹配到静态资源且非 `/` 开头的 API 路径时返回 `index.html`（支持 hash 路由时可不做，需实测确认）。
  - 好处：无跨域、无 CORS 白名单、无需第二个端口；前端 `apiBase = ""` 即同源相对路径。
  - nginx 反代作为后续可选方案，**本期不做**，文档保留说明即可，避免两套并存增加验证成本。
- 后端 CORS 收紧：现在 `allowedOrigin("*") + allowCredentials(true)` 等于允许任意站点带 Cookie 调接口，属于安全债。改为可配置白名单（`app.cors.allowed-origins`），生产默认只允许部署域名。

### 6.3 脚本与容器

```
scripts/
  dev.sh            # Linux/macOS：检测 java/node/mysql，起后端 + 前端
  dev.ps1           # Windows：等价实现，不再假设便携 MySQL 路径
  stop.sh / stop.ps1
docker-compose.yml  # mysql:8 + app（前端静态资源已打进后端 jar，同源部署）
Dockerfile          # 单镜像：JDK8 + 后端 jar（内含前端构建产物）
```

要求：
- `dev.sh` 用 `set -euo pipefail`，端口占用时给出明确提示而非静默失败。
- MySQL 连接串、端口、AI Key 全部通过环境变量注入，不写死。
- `docker compose up` 后访问 `http://localhost:8080` 即可用，无需任何手工建库（compose 初始化脚本自动导入 `database/base/*.sql` + `database/migrations/*.sql`）。
- 镜像构建分两阶段（frontend 构建产物 → backend 打包），最终只产出一个运行镜像。

### 6.4 验收

| 编号 | 操作 | 通过标准 |
|---|---|---|
| B4-1 | Ubuntu 20.04 干净环境执行 `./scripts/dev.sh` | 前后端起来，浏览器可登录 |
| B4-2 | macOS 执行同一脚本 | 同上 |
| B4-3 | Windows 执行 `scripts\dev.ps1` | 同上，且不依赖 PowerShell 5.1 特有语法 |
| B4-4 | `docker compose up` | 两个容器（mysql + app）healthy，`http://localhost:8080` 可登录并生成解析 |
| B4-5 | 前端代码全局搜索 `8081` | 除配置文件与文档外无命中 |
| B4-6 | 用局域网 IP 从另一台机器访问 | 登录、题库、解析均正常（这条同时解除了包 A 的阻塞） |

## 9. 风险与待确认

| 编号 | 风险 | 建议 |
|---|---|---|
| R1 | antd 4 + umi 3 的 less 主题变量在 build 后可能不生效 | 先在 dev 与 build 两种模式各验证一次再铺开改页面 |

| R5 | 前后端同时改 `requestServices.js` | 约定 B 只改 `API` 常量与新增配置接口，A 只追加学生端接口函数 |

## 10. 需求对齐结果（2026-11-18 已确认）

| 决策项 | 结论 | 对开发的影响 |
|---|---|---|
| 部署形态 | **同源部署** | 前端产物打进后端 jar，只暴露一个端口；删除 nginx 相关交付物；`publicPath` 改 `/` 是第一步且必须先单独验证 |
| 主题色 | `#2f54eb`（未反对，按默认） | 集中在 `.umirc.ts` 的 theme 变量，后续换色只改一处 |

| 暗色主题 | 本期不做（默认） | 但主题变量要集中，避免写死颜色，方便后续扩展 |

已确认项之外若需变更，走变更记录追加在本节，不要静默修改任务范围。
