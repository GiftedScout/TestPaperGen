# 数据库变更

## 1. 当前结构

| 脚本 | 说明 |
|---|---|
| `database/base/test_paper_generation_base.sql` | 基线结构：User / QuestionBank / QuestionLabels / QuestionMaterial / QuestionGenHistory / TestPaperGenHistory 六张表，含约 360 道样例题 |
| `database/migrations/001_ai_analysis.sql` | AI 解析模块增量：QuestionBank 追加 3 个字段 |

> 数据规模以实际库为准：当前开发库 `questionbank` 589 题、`user` 7 个账号、`testpapergenhistory` 10 条。`base` 脚本只提供约 360 题，其余为后续导入。
>
> 表名大小写：Windows 上 `lower_case_table_names=1`，实际表名为小写。迁移脚本做列存在性判断时用 `TABLE_NAME='questionbank'`，写 `QuestionBank` 会误判为不存在并重复 `add column`。

## 2. 增量内容（001）

| 字段 | 类型 | 默认 | 说明 |
|---|---|---|---|
| `analysis` | longtext utf8mb4 | NULL | AI 生成的试题解析 |
| `analysis_status` | tinyint | 0 | 0 无解析 / 1 已生成 |
| `analysis_update_time` | datetime | NULL | 解析最近更新时间 |

对应实体 `entity/QuestionBank.java` 与 Mapper 方法 `updateAnalysisById` 已同步扩展。

## 3. 执行

```bash
# 全新安装
mysql -u root -p < database/base/test_paper_generation_base.sql
mysql -u root -p < database/migrations/001_ai_analysis.sql

# 已有基线库增量升级
mysql -u root -p test_paper_generation < database/migrations/001_ai_analysis.sql
```

脚本内置幂等检查（information_schema 判断列是否存在），重复执行输出 `already exists, skipped`，不会报错。

## 4. 验证

```sql
USE test_paper_generation;
SHOW COLUMNS FROM QuestionBank LIKE 'analysis%';
-- 预期：analysis / analysis_status / analysis_update_time 三行
```

## 5. 回滚

```sql
ALTER TABLE `QuestionBank` DROP COLUMN `analysis`;
ALTER TABLE `QuestionBank` DROP COLUMN `analysis_status`;
ALTER TABLE `QuestionBank` DROP COLUMN `analysis_update_time`;
```

回滚仅丢失 AI 解析数据，题目与组卷数据不受影响；回滚后 AI 接口会因字段缺失报 SQL 错误，属预期，如需恢复重新执行 001 即可。
