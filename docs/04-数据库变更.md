# 04 - 数据库变更

## 1. 变更内容

AI 解析模块仅涉及 `QuestionBank` 表 **追加 3 个字段**，不改动、不删除任何既有列。

| 字段 | 类型 | 默认 | 说明 |
|---|---|---|---|
| `analysis` | longtext utf8mb4 | NULL | AI 生成的试题解析 |
| `analysis_status` | tinyint | 0 | 解析状态：0 无解析，1 已生成 |
| `analysis_update_time` | datetime | NULL | 解析最近更新时间 |

对应实体 `entity/QuestionBank.java` 与 Mapper 方法 `updateAnalysisById` 已同步扩展。

## 2. 执行方式

**全新安装**（无上游数据）：

```bash
mysql -u root -p < database/base/test_paper_generation_base.sql
mysql -u root -p < database/migrations/001_ai_analysis.sql
```

**已有上游数据库**（增量升级）：

```bash
mysql -u root -p test_paper_generation < database/migrations/001_ai_analysis.sql
```

脚本内置幂等检查（information_schema 判断列是否存在），重复执行不会报错，会输出 `already exists, skipped`。

## 3. 验证

```sql
USE test_paper_generation;
SHOW COLUMNS FROM QuestionBank LIKE 'analysis%';
-- 预期：analysis / analysis_status / analysis_update_time 三行
```

## 4. 回滚

```sql
ALTER TABLE `QuestionBank` DROP COLUMN `analysis`;
ALTER TABLE `QuestionBank` DROP COLUMN `analysis_status`;
ALTER TABLE `QuestionBank` DROP COLUMN `analysis_update_time`;
```

回滚影响：仅丢失 AI 解析数据，题目与组卷数据不受影响；回滚后需同步回退代码中的实体/Mapper 扩展（或直接保留代码，字段缺失时 AI 接口会报 SQL 错误，属预期）。
