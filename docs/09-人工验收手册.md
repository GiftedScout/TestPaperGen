## 2. 启动与停止

### 2.1 启动（推荐：一键脚本）

```powershell
cd D:\WorkBuddy\TestPaperGen
powershell -ExecutionPolicy Bypass -File scripts\local-start.ps1
```

脚本按顺序做三件事，全部为后台进程，日志写在 `logs\`：

1. 起 MySQL（3306），已运行则跳过
2. 起后端 jar（8081），已运行则跳过
3. 起前端 umi dev（8000），首次编译约 30–60 秒

全部就绪后自动打开 <http://localhost:8000>。控制台最后会打印：

```
Ready:
  UI       http://localhost:8000
  API      http://localhost:8081
  accounts admin/123456 (admin), teacher001/123456 (teacher)
```

### 2.2 停止

```powershell
powershell -ExecutionPolicy Bypass -File scripts\local-stop.ps1
```

按端口 8000 / 8081 / 3306 找到进程并停止；MySQL 走 `mysqladmin shutdown` 优雅退出，数据不会损坏。

### 2.3 端口约定（务必不要改）

- 前端 `src/config/requestConfig.js` 写死 `window.location.origin.replace(":8000", ":8081")`，**后端必须监听 8081**，否则所有接口 404。
- 前端 `publicPath = /static/`，只在 8000 端口 dev server 下正常，不要直接双击 `dist/index.html` 打开。

### 2.4 手工启动（脚本不可用时）

```powershell
# 1) MySQL
D:\WorkBuddy\tools\mysql\bin\mysqld.exe --defaults-file=D:\WorkBuddy\tools\mysql\my.ini --console

# 2) 后端（新开窗口）
$env:JAVA_HOME="D:\WorkBuddy\tools\jdk8"; $env:DB_PASSWORD="root"
D:\WorkBuddy\tools\jdk8\bin\java.exe -jar TestPapaerGen-Backend\target\test-paper-generation-3.0.0.jar --server.port=8081

# 3) 前端（新开窗口）
cd TestPapaerGen-Frontend
$env:NODE_OPTIONS="--openssl-legacy-provider"
npm start
```

## 4. 切换到真实大模型验收（P0 必做项）

Mock 模式只能验链路。真实解析需要 OpenAI 兼容的密钥，以 DeepSeek 为例（成本低、国内直连）：

```powershell
# 先停掉当前进程
powershell -ExecutionPolicy Bypass -File scripts\local-stop.ps1

# 带密钥重启（密钥只进后端 JVM 参数，不写文件、不进 git）
powershell -ExecutionPolicy Bypass -File scripts\local-start.ps1 `
  -AiKey "sk-你的密钥" `
  -AiBaseUrl "https://api.deepseek.com/v1" `
  -AiModel "deepseek-chat"
```

启动日志出现 `[cfg]  AI enabled for this run` 即为真实模式。判定点：

1. 解析内容为通顺中文，200 字以内，聚焦思路而非复述题目
2. 与给定答案不矛盾
3. 单题生成耗时 < 15 秒（`ai.timeout-ms=15000`）
4. 断网或错密钥时，前端提示友好文案（不是堆栈），题库其他操作不受影响

> 密钥也可用环境变量方式注入，避免出现在命令历史：先 `$env:AI_API_KEY="sk-..."`，再给后端加 `--ai.enabled=true`。

## 6. 已知限制与踩坑提示

1. **Mock 与真实的区别要写进结论**：`ai.enabled=false` 时解析文本固定为占位内容，只能证明链路，不能作为「AI 生成质量」的证据。
2. **MySQL 表名大小写**：Windows 上 `lower_case_table_names=1`，实际表名被存为 `questionbank`。`001_ai_analysis.sql` 用 `TABLE_NAME='QuestionBank'` 做存在性判断，在 Windows 上会判为不存在，**重复执行该脚本会报 duplicate column**。需要在已有库上重跑时，先手工确认列已存在。
3. **旧 FreeMarker 导出链未做 XML 转义**：不勾选解析时题干原样写入模板，含 `<`、`&` 的题干可能产出非法 XML（既有缺陷，本次未修）。验收时如遇 docx 打不开，先检查题干特殊字符。
4. **历史重导出无解析快照**：解析内容取自当前题库，题库更新会影响历史试卷的重导出结果。
5. **批量生成是顺序调用**：一次勾选几十题会逐题请求模型，耗时长且可能触发网关限流；建议单批 ≤ 10 题。
6. **批量入口无自动化测试**：PR #1 仅有构建验证，D 组是它唯一的回归防线，务必实机点一遍。
7. **前端 dev 偶发 EPERM**：`src/.umi` 下 babel-loader 缓存被占用时报错，`rm -rf src/.umi` 后重试即可，非代码问题。
8. **端口 8081 是硬编码映射**：换后端端口必须同步改 `src/config/requestConfig.js`。
