# 01 - 需求摘要

> 来源：《软件工程实践》需求分析报告（课题名称：在线组卷系统 TestPaperGen，完成时间 2026.10.10）
> 本文档提取报告中的有效信息，作为 TestPaperGen 二次开发的唯一需求基准。

## 1. 项目定位

| 项 | 内容 |
|---|---|
| 项目名称 | 在线组卷系统 TestPaperGen |
| 项目性质 | 基于成熟开源组卷系统（TestPapaerGen-WebApp）的**二次开发** |
| 核心目标 | 减轻教师出卷负担：保留原有组卷能力，**新增 AI 辅助生成试题解析** |
| 核心用户 | 高校授课教师（编制课堂练习、作业、考试试卷） |
| 次要用户 | 系统管理员（账号管理、基础维护） |
| 潜在用户 | 培训机构授课老师（批量出题、组卷） |

## 2. 问题背景

1. 人工组卷需手动筛题、搭配题型/难度/章节，A/B 平行卷重复工作量大；
2. 现有题库只存题干与答案，**缺少配套试题解析**，教师需手动补写；
3. 试卷排版与格式调整占用备课时间，整体出卷流程繁琐。

## 3. 功能需求

### 3.1 普通教师角色

| # | 功能 | 要点 |
|---|---|---|
| 1 | 账号登录注册 | 未登录禁止访问业务功能；登录后可维护题库、组卷 |
| 2 | 题库资源管理 | 选择题/判断题/填空题/阅读题/设计题增删改查；Excel 批量导入；可查看题干、答案、**解析** |
| 3 | **AI 生成试题解析【创新】** | 选中题目一键生成；后端调大模型；解析入库；导出时可选择是否附带 |
| 4 | 手动组卷 | 浏览题库，勾选题目加入试卷 |
| 5 | 自动算法组卷 | 按章节、难度、题型数量、总分等条件，遗传算法 + 贪心算法；支持 A/B 平行卷 |
| 6 | 试卷导出与历史管理 | 导出 Word 试卷与参考答案；出卷历史；历史试卷二次编辑 |
| 7 | 数据可视化 | Echarts 查看题库、试卷的题型/难度分布 |

### 3.2 系统管理员角色

| # | 功能 | 要点 |
|---|---|---|
| 1 | 账号管理 | 查看全部注册账号，基础管理维护 |
| 2 | 系统基础维护 | 查看运行状态，保障题库、试卷数据可用 |

## 5. 非功能需求要点

- **性能**：普通增删改查 < 1s；自动组卷算法 < 10s；AI 生成解析接口超时 15s，超时返回友好提示。
- **安全**：拦截器登录鉴权；**大模型 API 密钥存放后端配置，前端不暴露密钥**；不同用户数据逻辑隔离；输入合法性校验。
- **易用性**：Web 界面简洁直观；错误提示使用自然语言，不展示后端异常；导出 Word 排版规整，兼容 Office/WPS。
- **可扩展**：AI 解析模块与原有组卷模块**低耦合，不修改原有遗传算法核心逻辑**；预留 PDF 导出、试题标签扩展空间。

## 6. 技术选型（与上游一致）

后端 Java SpringBoot；前端 React + Umi.js；数据库 MySQL；算法遗传 + 贪心；AI 调用第三方大模型 API；可视化 Echarts；文档导出 OpenXML（Apache POI）生成 Word。

## 7. 已识别的技术难点与应对

| 难点 | 应对策略 | 本框架落点 |
|---|---|---|
| 大模型返回解析格式不稳定 | 后端增加返回内容校验，异常返回给出提示，不影响组卷主流程 | `AiAnalysisService.validate()`：非空校验、长度上限、去 Markdown 围栏；异常抛 `AiException` 转友好提示 |
| 遗传算法组卷参数调优 | 沿用开源项目已调试好的算法逻辑，不做大改动 | 算法代码零改动 |
